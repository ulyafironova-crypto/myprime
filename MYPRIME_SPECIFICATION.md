# MyPrime — спецификация MVP

## 1. Контекст и цель

Создать личное mobile-first веб-приложение (PWA) для учёта спортивных тренировок и выполнения недельных целей. Пользователь должен быстро фиксировать состоявшиеся тренировки, видеть качество каждой недели в календаре и отслеживать историю пробежек.

Первая версия рассчитана на одного пользователя. Она не требует регистрации, пароля, облачного сервера, синхронизации, напоминаний или социального функционала.

Главный принцип: **минимум действий для записи тренировки, максимум ясности при просмотре прогресса**.

## 2. Формат продукта

- Адаптивное мобильное веб-приложение, оптимизированное для телефона.
- Устанавливаемое на главный экран как PWA.
- Работает без постоянного интернета после первой загрузки.
- Интерфейс и все тексты — на русском языке.
- Данные хранятся локально в браузере устройства. Для MVP предпочтителен IndexedDB; допустим `localStorage` при простой реализации.

> Ограничение MVP: при очистке данных браузера или смене устройства записи могут быть потеряны. Экспорт, импорт и облачная синхронизация не входят в эту версию.

## 3. Недельные цели

При первом запуске использовать стартовые цели:

| Тип тренировки | Цель на неделю |
| --- | ---: |
| Бег | 3 |
| Силовая | 2 |
| Функционально-силовая | 1 |

Итого: 6 тренировок в неделю.

Цели должны задаваться **отдельно для каждой календарной недели** в простом экране или нижнем листе «Цели на неделю». Пользователь выбирает текущую или будущую неделю и указывает количество беговых, силовых и функционально-силовых тренировок именно для неё.

Пример: для одной недели пользователь задаёт только «Бег — 3», выполняет три пробежки и получает статус «Идеальная». Для следующей недели может задать «Бег — 3», «Силовые — 2», «Функциональные — 1»; идеальность следующей недели оценивается уже по этому новому набору.

Изменение сохраняет историю: каждая неделя оценивается по целям, закреплённым за этой неделей, а не по текущим целям пользователя. Если для недели цели ещё не настроены, использовать стартовые значения 3 / 2 / 1.

Неделя длится с понедельника по воскресенье. Тренировка относится к неделе по своей дате. При редактировании даты автоматически пересчитываются обе затронутые недели.

Перевыполнение сохраняется в данных и отображается в счётчике (например, `4 / 3`), но не получает отдельного цвета или статуса: после достижения 100% неделя считается идеальной.

## 4. Оценка и цвета недель

Процент выполнения рассчитывается по количеству тренировок, с ограничением результата 100%:

`min(выполнено по всем типам с учётом целей / сумма целей, 100%)`.

Для каждого типа учитывается не больше его цели. Так лишняя пробежка не компенсирует невыполненную силовую: при 4 пробежках и 0 силовых результат будет `3 / 6`, а не `4 / 6`.

| Выполнение | Статус завершённой недели | Цвет |
| --- | --- | --- |
| 100% | Идеальная | ярко-зелёный |
| 80–99% | Хорошая | салатовый |
| 50–79% | Средняя | жёлтый |
| 1–49% | Слабая | светло-красный |
| 0% | Нет тренировок | нейтральный серый |

Текущая незавершённая неделя не должна получать негативную оценку. Она отображается как «В процессе» с текущим прогрессом, например `3 из 6`. Её итоговый статус фиксируется после окончания воскресенья.

Цвет не должен быть единственным носителем смысла: всегда показывать текстовый статус и/или числовой прогресс.

## 5. Информационная архитектура

Нижняя навигация содержит четыре раздела:

1. **Календарь** — главный экран и оценка недель.
2. **Добавить** — создание тренировки.
3. **Бег** — общий журнал всех пробежек.
4. **Настройки** — недельные цели, тема и локальные сведения.

## 6. Экран «Календарь»

- Показывает один месяц и позволяет перейти к предыдущему или следующему.
- Отображает сетку дней и недель с понедельника по воскресенье.
- Каждая календарная неделя подсвечивается одним цветом по её результату.
- Текущий день имеет отдельный заметный маркер.
- Неделя, пересекающая границу месяца, должна оставаться единым объектом оценки.
- Нажатие на любую неделю открывает «Детали недели».
- На экране должна быть заметная кнопка `+` для быстрого добавления тренировки.

## 7. Экран «Детали недели»

Показывать:

- диапазон дат недели, например «10–16 августа»;
- статус и общий прогресс: `4 из 6 тренировок`;
- прогресс по каждому типу:
  - Бег: `2 / 3`;
  - Силовые: `1 / 2`;
  - Функционально-силовые: `1 / 1`;
- список всех состоявшихся тренировок недели, отсортированный по дате (новые сверху или хронологически — выбрать единообразно);
- краткую сводку бега, если в неделе есть пробежки:
  - общий километраж;
  - суммарное время;
  - средний темп, взвешенный по дистанции;
  - средний пульс, взвешенный по длительности.

Сводка должна быть компактной: небольшая карточка из 2×2 показателей, без графиков и отдельного экрана.

У записи в списке должны быть понятные действия «Редактировать» и «Удалить». Удаление требует подтверждения.

## 8. Добавление и редактирование тренировки

Путь должен быть коротким: выбрать тип → заполнить нужные поля → сохранить. По умолчанию дата — сегодня. После сохранения показать короткое ненавязчивое подтверждение и обновить календарь.

### 8.1. Бег

Обязательные поля:

- дата;
- дистанция в километрах;
- темп в формате `мм:сс / км`;
- длительность в минутах;
- средний пульс.

Одна запись бега считается одной беговой тренировкой независимо от дистанции.

Проверки:

- расстояние, длительность и пульс — положительные числа;
- темп — валидный формат минут и секунд;
- все обязательные поля должны быть заполнены понятными сообщениями об ошибке.

### 8.2. Силовая тренировка

Поля:

- дата;
- фокус: `Верх` или `Низ`;
- свободная текстовая заметка «Упражнения и подходы».

Пример заметки: `Жим гантелей — 3×10, тяга блока — 4×12`.

Каждая запись считается одной силовой тренировкой.

#### Повтор предыдущей силовой

При создании силовой показывать действие `Повторить прошлую тренировку`.

- Для выбранного фокуса («Верх» или «Низ») приложение подставляет текст заметки из последней силовой тренировки того же фокуса.
- Пользователь может изменить текст перед сохранением.
- Если подходящей прошлой записи нет, действие не показывается или неактивно с понятным пояснением.
- Повтор не копирует дату: дата всегда остаётся сегодняшней по умолчанию или выбранной пользователем.

### 8.3. Функционально-силовая тренировка

Единственное поле — дата. Дополнительные показатели не требуются.

Каждая запись считается одной функционально-силовой тренировкой.

### 8.4. Общие правила

- Любую тренировку можно редактировать и удалить.
- После изменения типа или даты пересчитывать календарь, прогресс и беговую сводку.
- Не нужно фиксировать запланированные или пропущенные тренировки: в приложении хранятся только состоявшиеся.

## 9. Раздел «Бег»

Показывает единый журнал всех пробежек, без группировки по неделям. Сортировка по умолчанию — от новых к старым.

Для каждой пробежки отображать пять показателей:

| Дата | Километры | Темп | Минуты | Пульс |
| --- | ---: | ---: | ---: | ---: |

На мобильном экране допустимы горизонтально прокручиваемая таблица или компактные карточки, но все пять показателей должны быть доступны без открытия записи.

Нажатие на пробежку открывает редактирование.

В MVP не нужны графики, личные рекорды, фильтры и GPS-запись маршрута.

## 10. Настройки

Минимальное содержимое:

- выбор текущей или будущей недели и редактирование её целей;
- выбор темы: светлая, тёмная, как в системе;
- короткое пояснение о локальном хранении данных.

## 11. Дизайн-система

Дизайн-система будет дорабатываться отдельно. На этом этапе не нужно создавать окончательную визуальную айдентику, сложные иллюстрации или жёстко зашивать значения цветов и отступов в компоненты.

Требования к реализации:

- вынести цвета, типографику, радиусы, отступы, тени и статусы в дизайн-токены (например, CSS custom properties);
- компоненты должны использовать семантические токены, например `--color-week-ideal`, а не конкретные hex-значения;
- предусмотреть светлую и тёмную тему;
- использовать доступные контрастные цвета и не передавать смысл только оттенком;
- сохранить единообразные компоненты: кнопка, поле ввода, карточка, нижний лист, бейдж статуса, строка тренировки;
- обеспечить комфортные области нажатия на телефоне и не скрывать основные действия за мелкими иконками.

Пока дизайн должен быть спокойным, чистым и функциональным. Приоритет — понятный календарь и быстрый ввод, а не декоративность.

## 12. Модель данных

```ts
type WorkoutType = "run" | "strength" | "functional_strength";
type StrengthFocus = "upper" | "lower";

type Workout = {
  id: string;
  type: WorkoutType;
  date: string; // YYYY-MM-DD в локальной дате пользователя
  createdAt: string;
  updatedAt: string;

  // Только для бега
  distanceKm?: number;
  paceSecondsPerKm?: number;
  durationMinutes?: number;
  heartRate?: number;

  // Только для силовой
  strengthFocus?: StrengthFocus;
  notes?: string;
};

type WeeklyGoals = {
  run: number;
  strength: number;
  functionalStrength: number;
};

type GoalVersion = {
  weekStart: string; // понедельник недели в формате YYYY-MM-DD
  goals: WeeklyGoals;
};
```

В хранении должна быть запись `GoalVersion` для каждой недели, цели которой пользователь настраивал. Прошлые недели не меняют оценку после настройки целей другой недели.

## 13. Не входит в MVP

- регистрация, пароли, несколько пользователей;
- сервер, облачная синхронизация, резервное копирование;
- экспорт и импорт;
- напоминания и уведомления;
- планирование тренировок по конкретным дням;
- предустановленные упражнения, программы, видео и таймер отдыха;
- сон, питание и другие привычки;
- причины пропусков;
- награды, социальные функции и рейтинги;
- графики, рекорды, фильтры пробежек;
- Apple Health, Garmin, Strava и любые внешние интеграции.

## 14. Критерии готовности

1. Приложение устанавливается на телефон как PWA и работает после первой загрузки без интернета.
2. Пользователь может создать, отредактировать и удалить все три типа тренировок.
3. Бег требует дату, километраж, темп, длительность и пульс.
4. Силовая тренировка поддерживает выбор «верх/низ», свободную заметку и повтор последней заметки того же фокуса.
5. Пользователь может задать разные цели для текущей и любой будущей недели; каждая неделя сохраняет собственные цели и оценивается независимо.
6. Календарь правильно рассчитывает и показывает статус каждой завершённой недели; незавершённая текущая неделя отображается как «В процессе».
7. При нажатии на неделю открываются её тренировки, прогресс по целям и компактная сводка бега.
8. Раздел «Бег» содержит единый список с датой, километрами, темпом, минутами и пульсом.
9. Смена даты, редактирование или удаление записи немедленно обновляет всю связанную статистику.
10. Интерфейс построен на дизайн-токенах и готов к последующей доработке дизайн-системы.
